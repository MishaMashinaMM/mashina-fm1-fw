3. Deliberate physical reset

PREPARE issues WebMIDI command 101, a read-only scan. It returns a short-lived one-time nonce only if all expected sectors are valid. COMMIT issues command 102 only after a second explicit confirmation, using the nonce within 15 seconds. The firmware repeats its entire sector preflight before writing. An interrupted erase or marker commit must be handled as a recovery case — NEVER automatically retry it.

4. Optional: restore original USER presets after reboot (skip for fresh start)

Only after the fresh FM1 has been power-cycled. The original 43-object backup can restore its USER 001–032 banks and FM6/drum sidecars without importing old FUN projects or old settings. All target USER slots must be empty; the browser verifies every complete sound after writing. This is a separate, explicit physical write and is not atomic across three banks.

A restore failure must be investigated before any retry. Do not load old project/settings data into MPR1.

5. Verify persisted sounds after a SECOND power cycle (read-only)

The initial USER restore readback may come from the device's RAM. After successful restoration, power-cycle the FM1 again, reconnect, and verify all 304 bytes of each original sound directly from the newly booted device. This stage sends NO writes.
