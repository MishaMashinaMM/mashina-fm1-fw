Connect and prepare

Use this manager with a MASHINA v0.15 FM1 and a desktop Chrome or Edge browser. It does not install firmware or initialize storage. For a downloaded ZIP, extract all files into one folder, open a terminal in that folder, run python3 -m http.server 8000 and open http://localhost:8000/. Keep the server running while using the library.

Connect FM1 using the button. The BACKUP tab is the landing page. The connection progress dialog shows the complete device read and verification. Leave the FM1 connected and wait until the operation completes. The device data is checked automatically. No download or file selection is required. Save complete backup downloads a JSON when you choose; Refresh device data repeats the automatic read and verification.

During a device transfer, stop playing and leave USB connected. The manager verifies device data before and after writing. Successful writes update the in-memory snapshot without downloading anything. If the FM1 changes outside the manager, refresh its data before writing again.

Offline collections and performance files

Available presets is a fully editable offline collection. It starts with the factory catalog; use Add factory sounds to add missing factory entries again, Add device sounds or drag device slots to add sounds from the FM1, and Import JSON to merge another file. Remove any preset with ×, or select multiple and click Remove selected (Delete also works when the collection has focus). Save collection asks for a filename and exports every remaining sound, including entries outside the current search or filter. The .json extension is added automatically. Open collection replaces the list with a saved file, without automatically adding factory sounds. None of these actions modifies the FM1 or its staged writes. The same sound collection JSON can be opened or imported in either USER or LIBRARY, regardless of which tab saved it. Drag its sounds into the desired device positions; a collection has no fixed destination mapping. PROJECTS collections remain separate. Collections have no fixed slot limit; save the JSON before closing the page. Exact duplicates merge; different sound variants are retained. Double-click a preset name or click its pencil to edit the name directly in the row. Enter or clicking outside saves the name; Escape cancels. The name field uses a grab cursor until editing starts. Offline names change immediately; device names are staged for the corresponding Write changes button. Names use 1–12 printable ASCII characters. Rename a project section by its name, or rename every occupied A–D section using the project label (device) or project title (offline).

Multi-selection: click an item to select it; Ctrl-click toggles individual items, Shift-click selects a range, Ctrl+A selects all matching the current source filters (including other pages) or all occupied device positions, and Escape clears the selection. Drag any selected item to move the group. Source groups fill consecutive slots in list order starting at the drop target. Device groups fill consecutive slots in slot order, swapping displaced sounds or projects into vacated positions. Groups that do not fit are rejected as a whole; there is no wraparound or partial staging. Drag selected device items into the right-hand list to add them to the offline collection. On PROJECTS, each row selection represents the complete A–D project; the individual A–D chips still drag a single section.

Drag sounds onto the left-hand numbered slots. Drag an existing slot onto another to swap or move its staged sound; orange rows indicate pending edits. Drag an offline project onto any section of a destination project to stage all four A–D sections (including empty ones); drag an A–D chip to stage only that section. Projects retain numeric preset references. Check the required USER presets and LIBRARY sounds before applying.

BACKUP → Performance file → Save complete performance exports the base device snapshot plus all pending USER, LIBRARY and project edits, current live references and settings. Select an existing complete backup and Open source offline to arrange it without a device. Reopen the resulting file in the complete backup panel to load it into an initialized FM1. No USB write occurs during drag/drop or export.

USER · 001–032

Editable sounds stored on FM1. Drag sounds to empty or occupied slots. Drag an existing slot onto another to move or swap the sounds. Slot numbers keep their project references; currently loaded sounds can be replaced and the live performance reloads after writing. Clearing a referenced USER slot is refused if it would leave a missing sound.

  1. Under Available presets, use Import JSON, or choose a source from the connected device or factory catalog.
  2. Drag a source sound onto a numbered USER slot, or expand Manual selection / fixed-slot import and choose source and destination. Alternatively, Queue all imported sounds skips exact duplicates and fills available empty slots.
  3. Review the USER write queue, click Write USER changes and confirm.

Export device USER sounds saves the complete stored sound records, including applicable drum/FM6 companions. It does not include projects or global settings.

LIBRARY · 033–128

96 factory-backed positions; overrides can be installed without reflashing. All 107 factory source sounds are available in the packaged catalog.

  1. Drag a sound from the right-hand list onto a numbered LIBRARY slot, or use manual selection. For an existing override, Revert to factory preset returns the position to its factory sound.
  2. Use Queue imported slot mapping only for packs whose saved positions are the intended LIBRARY destinations. Review the queue.
  3. Click Write LIBRARY changes and confirm.

Changing a preset changes what every referencing section loads. The confirmation lists affected project sections. No separate permission checkbox is needed. Currently loaded LIBRARY presets can also be replaced or reset. The live performance is reloaded after writing, preserving its track references and settings; stop playing during the transfer.

Export device LIBRARY overrides exports stored overrides, not compiled factory fallbacks.

PROJECTS · 8 × A–D

Each section stores track preset references and project settings, not independent copies of its sound patches. Save the sounds first.

  1. Export device projects creates a projects-only JSON.
  2. Import JSON shows the imported and device sections. Choose changed sections individually or click Select changed sections. Empty source sections can clear selected occupied destinations.
  3. Write PROJECT changes applies the selection after confirmation. Required USER references must already exist. Recall the section on FM1 to hear it.

Writing project sections does not install sounds. Preserve matching sound packs or a complete backup for portable projects.

BACKUP · whole device

A complete logical backup contains the supported USER and LIBRARY records, 32 project sections, current performance and settings. It is not a raw flash dump or firmware installer.

  1. Connect FM1; device capture and verification are automatic.
  2. Under Write a complete backup, choose the source JSON.
  3. Review the changes. Write complete backup may overwrite or clear stored slots and change the current performance. Click WRITE in the confirmation dialog only if the listed changes are intended; CANCEL makes no changes.
  4. Save a local backup whenever desired. The read-back is verified automatically in memory. The written live performance becomes unsaved rather than overwriting a stored section.

Do not use this operation to migrate a legacy firmware backup. Use a complete backup from a compatible MASHINA version. Import individual sound collections separately.

When a transfer is blocked or fails

  • Device changed since verified backup: the safety check found a difference before writes. Refresh device data, review the intended changes again.
  • Unsaved sound / backup cannot be captured: save or reload the relevant preset before backing up; do not discard edits you want to keep.
  • STOP after acknowledged operations / failed read-back: some changes may already be stored. Save the available diagnostic read-back if desired. Do not retry automatically, initialize or reflash. Inspect the actual state before deciding on recovery.
